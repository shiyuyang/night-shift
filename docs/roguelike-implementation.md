# 当前可玩版本：先收敛基础搜寻与逃生

按试玩反馈，先解决“交互物体不易识别、房间散乱”，暂停上一轮大规模机制叠加。调研文档中的完整机制列表属于后续候选，不代表全部启用。

## 主循环
找铜钥匙 → 搜箱取得房门钥匙与保险丝 → 开铜锁箱 → 开房门与封箱 → 集齐三枚保险丝 → 撑过 8 秒供电并逃生。门首次开锁消耗对应钥匙，已开锁的门可开关。通关不选奖励。

首关仍为固定 LDtk 地图与情境教学。第二关起闪光、诱饵、绷带各 1（补给关额外 1 闪光），保留主追踪者、压力喘息和观众指令预算。

## 两种额外物体
- **补给药柜**：矮柜、旧象牙色表面、红色药品十字；靠近显示 `[E] 药柜 · 补给`。一次 E 领取一件随机道具，结果由种子决定，没有概率确认和随机报警。获得结果在右侧独立区域显示名称、数量和现有库存 4 秒，道具格同步 +1；携带满时物品留柜，可稍后再取。搜空后呈现打开的空隔板，不能重复领取。
- **藏身柜**：明显更高的冷绿色铁柜、浅色人形标牌；靠近显示 `[E] 藏身柜 · 躲藏`。被怪物目击时拒绝进入，先拉开距离；最长藏 8 秒，柜顶提示剩余时间，E 或移动离开。

每局最多各一个，布置于主通道之外，优先靠墙或既有家具。柜子外形不同，标识绘制在物体上；近距离显示统一 NightPixel 字体的用途提示，不添加大面积发光框。普通床、货架、机器不显示交互标识。

暂不生成：玻璃、漏电、蒸汽、噪声机器、手摇捷径、守门者。相关底层逻辑与 LDtk 家具模块文件暂留供后续迭代，不参与当前关卡。

## 空间约束
完整保留原 LDtk 隔墙、家具、门、灯位、事件区域。锁房箱子已移到房间内部，与门保持至少 90 像素间距，避免箱前 E 误触关门；原备用点的隔门触及问题一并修正。随机只作用于原物资点附近 ±24 像素的 8 像素网格，不重排房间、不切墙、不跨场景拼家具。附加柜子不占主走廊，需验证前方可接近，并把两个柜子的扩大安全区同时视为障碍验证主线可通。

该版本主动缩小地图变化量，优先验证可读性和基础玩法。未来的布局变化应使用人工设计的完整房间与固定门口契约，再考虑拼接。

## 验证与记录
`npm test` 验证 600 个主题/种子组合：LDtk 墙体和家具不变、物资变化、完整锁链可解、怪物区域连通、失败回退；附加柜子验证一次领取与藏身规则。
`npm run test:browser:night2` 实际键盘完成三个主题的钥匙、开箱、供电、逃生，并验证药柜领取、藏身及暂停计时。
局内统计保留本地最近 30 局，不上传。结算显示搜寻与藏身次数，旧记录兼容字段继续保留。

## 提示与随身 HUD
钥匙、箱子、房门、出口和两种柜子的交互文字统一绘在实际物体上方，使用 NightPixel 字体，按当前钥匙和开锁状态显示动作或缺少条件。

- 左上内侧：无底板的生命数字与加长加粗的细实心像素血条，仅危险或治疗时补充状态文字。体力主要在人物脚边反馈，恢复满后收起；教学保留体力说明，菜单可查看完整生命/体力数值。
- 右上内侧：保险丝、钥匙、电量。
- 上方中央：紧张阶段供电倒计时。
- 右侧中上部：独立获得结果，带对应像素图标、名称、增量和库存；不再同步写入环境字幕。
- 中部偏下：无底板的短句字幕，18px 基准字号随实际画面适度缩放；独立显示，不被获得结果覆盖。
- 下方中央：仅保留 F/R/Q 三个无底板像素图标与次数。绷带统一使用带提手的十字药箱图标，效果与名称不变。

竖屏为状态预留顶部空间，为获得结果和快捷道具分别预留下方两行；相机内部仍为 640×384，适配不改变模拟范围。菜单和结算隐藏对应游戏 HUD。所有领取时限随模拟时间暂停和重置。

浏览器检查包含真实领取后触发侦察，确认两类消息同时存在；布局测试同时显示长环境字幕、获得结果和倒计时，检查桌面、超宽、方形、短横屏、手机及紧凑竖屏下无重叠、无越界。布局测试的组合状态为 DOM 展示用例，不代替实际游戏行为验证。

HUD 按实际游戏显示宽度适度缩放，桌面内缩约 8%；取消面板背景、边框和整块高亮，使用薄暗色字边保证可读。开局不再播放怪物类型及通用按键说明，仅保留情境教学、靠近物体的交互提示和实际事件警告。

生命条使用 细实心像素条（桌面基准 180×6px），灰白填充，无内部格线，无渐变、倒角、边缘碎点或底板，填充按 60 档像素步进变化，数字仍显示真实生命值，低血量变为锈红色，受伤保留短暂失血残影，治疗时按模拟时间回填；竖屏按左上区域宽度适配。

本轮怪物与基础压力改造见 `monster-encounter-design.md`。拾取反馈在横屏游戏视口右侧内收至 22%、顶部 45%，保留透明样式，并与环境字幕、供电提示分开。
