# 怪物行为优化与难度复测（2026-09-11）

本轮实现了[优化方案](monster-balance-optimization-plan.md)，采用 **15 秒无接触、脱战后 10 秒并行保护、休息夜 20 秒**。数值是当前候选，不代表已经找到了适用于所有玩家的最佳难度。哭泣者、敌人数、速度、伤害、体力、破门时长和补给没有随本轮再次调整。

## 已落地

- 第四夜起、第三个任务箱之前按可达区域轮换巡逻；空闲且无接触达到阈值时调整覆盖区域。正在追击、搜寻、破门、受控或哭泣者造成近身压力时不额外改派。两个计时条件同时满足即可，不叠加成 25 秒。路线不读取隐藏玩家坐标。
- 主怪巡逻者与出口巡逻者实际命中后各自收招 0.7 秒，停步和停攻击，保留线索及朝向。不会暂停另一只怪；站着不动仍会再次受伤。
- 诱饵与环境机器须先被听见：听声者小于 260、可隔墙；畏光者和巡逻者小于 180、需要无遮挡。每次发声独立标识，未听见不能改变追击或破门，已接收不会在边界反复刷新。
- 出口怪保留六秒守候和近距看见玩家时的提前响应，之后沿出口前两处合法点巡查。旧线索行进最多四秒、局部搜索三秒，无新发现再沿路径返回。持续看见玩家时不会被计时器赶回出口。
- 伤害记录具体攻击者，道具记录实际命中者；收招时长与道具控制、完整脱战分别统计。绘制回放执行 Phaser 实际渲染。

第六夜的出口交互标记与怪物碰撞体重叠，不能直接当作寻路起点。出口巡查先选择附近合法起点，并重新检查到路口的实际最短路程；七图检查均有合法巡查点。

## 如何解读

**仓库贴身伤害尖峰缓解。** 第九夜种子 2 的最终阶段总伤害从 200 降为 20，倒计时内从 180 降为 20；第 37 夜种子 3 的最终阶段总伤害从 160 降为 60，倒计时内从 160 降为 40，由死亡变为通关。两例调整后的最终阶段伤害都来自出口巡逻者。它仍能造成威胁，未要求机器人无伤。

**收招本身不能解决全部夹击。** 单加收招时，第 37 夜种子 3 仍死亡：出口怪伤害 160→140，但主怪额外造成 20，总伤害未降。声源接收修复后该例才通关；随后加入出口巡查与日常路线，最终伤害为 60。本轮按收招、声源、出口、日常顺序逐批运行累计候选；除收招外，没有把各项单独回装原版进行全组合消融，不能精确分摊每一项的独立收益。

**中庭增加了接触机会，并非持续追杀。** 第四夜附近搜索种子 0/3 的日常有效威胁分别从 0 增至约 5.5/4.0 秒，均未在日常受伤。逐箱搜索种子 2 则从 1.15 秒威胁变为约 0.3 秒威胁加 3.4 秒近距控制，并使用一个闪光、受到一次主怪伤害。该样本仍有长时间安静段，不能声称已经稳定实现脱战后 20–25 秒再次接触；15 秒只是允许改派，行进与绕行仍决定是否碰面。

**第一夜出现增伤，需要保留为试玩重点。** 种子 0 普通策略从无伤变为日常和最终阶段各受伤 20，总伤害 40；第二夜种子 0 的伤害、威胁和道具消耗保持一致。补测前两夜种子 1/2 的普通与保守策略共八局均通关。教学保护与物资规则未改，但不能因通关就忽略第一夜的新接触风险。

**最终压力没有普遍下降。** 第四、五、六夜的多个倒计时样本增加了实际威胁；第九夜种子 3 也从无伤变为 40 伤害。仓库尖峰下降与其他路线压力上升同时存在，下一轮真人试玩优先覆盖第一夜与中庭最终撤离。

## 验证与证据

- `npm test`：215 项普通测试与 1,400 组地图检查全部通过，0 回退、949 个不同布局。本轮与两路浏览器并行时总计 36.0 秒；这不是单独 CPU 性能对比。
- 实际机制：主怪/出口怪命中后停步、走开和站立对照；同帧诱饵改变破门意图；环境机器接收；日常调度阶段边界。七图出口等待、追丢返回、再次发现玩家均检查。
- 听声者与畏光者：日常 20 例、最终十秒 20 例通过；最终速度 121 下，闪光后听声者轻走四秒间距约 211，照光转身对畏光者三秒间距约 500。保留原反制窗口。
- 第九夜种子 2 实际绘制回放 **1,332 步状态指纹全部一致**。渲染入口的修复发生在校准批次之后，未改无绘制路径；回放显式允许源码版本不同并仍逐步断言状态相同。
- `npm run test:balance:regression`、构建与 TypeScript 检查通过；出口专项修正了重开时等候条件，等新关卡实际创建后另外复跑。
