# 箱子与钥匙的位置规则

本轮调整只改变物资位置与分布，保留三只任务箱的钥匙链、空任务箱的难度阶梯，以及每局两只道具箱有物资的规则。第一夜保留固定教学路线和四只道具箱；后续道具箱仍为四至六只。

## 选点顺序

- `game/search-spots.json` 为每张地图保存 `key`、`task`、`sealed` 三组候选位置。前两只任务箱共用未锁房间的 `task` 池：先随机房间，再随机该房间内的位置，房间不再绑定无锁箱或铜锁箱。两只箱子分处不同房间或储物区，至少相距 180 像素；铜锁箱与地面铜钥匙至少相距 80 像素。
- 候选位置覆盖七张地图的多个储物区域，优先靠墙、靠家具边角，避开门口，并检查交互与怪物通行。第一夜固定位置仍来自 `maps/ward.ldtk`；`game/maps/*.json` 由导出工具生成。
- 最后一只任务箱单独从锁房的 `sealed` 池选择，始终有锁并提供保险丝。额外的无锁空箱可以出现在锁房里，但不会替代这只任务箱；第一夜的空箱仍固定安排在开门后才能进入的区域。
- 非教学关的铜钥匙不再只放在出生点附近的房间。先在具有合法开场路线的房间中随机选择，再选择该房间的钥匙与首箱组合，避免候选坐标较多的房间占据大多数结果。所有钥匙都能在门未解锁时取得。
- 第三夜起，钥匙和首箱继续避开出生点直视，至少间隔 300 像素，且需要绕过遮挡；第二夜保留原有 180 像素间隔规则。
- 道具箱优先覆盖不同地图方位，再填补尚无道具箱的房间或储物分区；长条房间按空间跨度细分。任务箱和空箱参与间距计算，但不占用该房间的道具箱名额。
- 优先放置四只道具箱，然后保留空任务箱位置，最后放置躲藏柜与额外道具箱。这样小房间的唯一可用位置不会先被空箱或躲藏柜占满。
- 不把道路、事件触发区、停尸柜伸缩区当作储物房间。仓库可利用货架区，手术室可利用手术区边缘，花园可利用长椅旁边。所有新家具仍需通过可绕开障碍物的完整路线验证。

## 空间约束

道具箱和躲藏柜之间至少间隔 96 像素，排序时优先争取 160 像素。道具箱分布的横向跨度至少 400 像素，纵向至少 200 像素；当其他物品占位导致布局无法满足数量与覆盖要求时，使用下一次确定性生成尝试，不把余下物资挤在一个角落。

箱体靠近建筑或家具，但保留碰撞和交互空间。道具箱与空任务箱的正面必须可达；任务箱允许从可见、可达的一侧操作，适应洗手间等狭小储物凹槽。主门、出口、钥匙链、最终撤离距离、怪物接近任务箱、停尸柜伸出后的通路，都沿用原有验证。

## 验证

2026-09-11：222 个普通测试通过；1,400 组地图通过，零回退、1,359 个不同布局（任务箱跨房间随机前为 1,167 个）。全地图测试覆盖箱子间距、前两箱不同房间、道具箱覆盖范围和靠近建筑/家具的断言；另外验证非教学关钥匙与两种前置任务箱各自能分布到多个区域。完整 CPU 测试的两阶段耗时 11.0 秒，属于本机单次记录。

第二至第八夜各抽样 30 个种子，每种前置任务箱实际覆盖 3–6 个房间或储物区，记录见 `output/task-room-variation/room-variety.json`。这证明房间分配已有变化，不代表已测得玩家探索时间增长。

运行 `npm run test:browser:containers`（需先启动 `http://127.0.0.1:5174/` 的 Vite）检查第一至第八夜的实际钥匙、开箱、开门及物资搜索交互，覆盖七张地图、固定教学和后续随机病房。该测试把玩家放到已验证可达的合法操作位置，保存游戏截图和交互记录；它是位置与交互检查，不代表无辅助通关或难度评估。

本轮第一至第八夜 seed 0 的交互检查全部通过，浏览器无脚本错误；记录与实际游戏截图保存在 `output/task-room-variation/browser/`。构建通过。

生成规则改变后，同一个种子的物品位置会变化，旧难度回放不能继续当作状态完全一致的基线；需要重新生成输入记录。本轮调整前后的 seed 0 布局保存在 `output/task-room-variation/`，此前靠墙与物资分布调整的记录保留在 `output/loot-placement/`。
