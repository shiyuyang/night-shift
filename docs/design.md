# 夜班档案：互动恐怖玩法设计

> 下文保留 0.1 初版设计基线。0.2 已实现内容、第二夜规则和后续优先级以 [迭代规划](roadmap.md) 为准；新的生成素材记录见 [art-prompts.md](art-prompts.md)。

## 体验目标

一局约 3–5 分钟，让主播即使没有礼物也能完成“探索、找道具、躲追逐、逃生”的完整循环。俯视角医院、低饱和绿色、监控时间码、扫描线和有限照明共同制造不安；UI 将生命、能量和目标常驻，方便观众理解正在发生什么。

观众的行为改变主播的决策，而非仅播放弹窗。熄灯改变视野，幽灵迫使改道，电量允许疾跑，庇护创造抢道具的时间窗口。援助和捣乱各两种，避免直播间只剩单向惩罚。示例礼物名和数量是设计占位，未映射真实 TikTok 礼物 ID 或价格。

## 当前规则

医院是一张固定地图，三个保险丝分别位于左上病房、下方库房和右上隔离病区。墙体阻挡玩家，幽灵穿墙追逐。重复恐怖事件刷新而非叠加；最多一只幽灵，庇护与受击间隔提供恢复机会。暂停会冻结计时、追逐和伤害，暂停中收到的礼物不追补。

直播画面支持全屏；生存指南打开时暂停游戏，需要主播手动继续。移动端页面可浏览，但游戏目前依赖键盘，不包含触摸摇杆。

## 事件边界与正式接入

```
TT 礼物 webhook
  → 服务端 TT 适配器（待协议确定）
  → 签名 / 房间 / 去重 / 限流
  → { id, command, viewer, time }
  → SSE 或 WebSocket
  → 游戏命令分发
  → 计时效果 / 状态反馈 / 事件记录
```

协议确认后需要确定：签名算法、礼物 ID 与连击结算规则、消息唯一 ID、房间标识、重试策略、时间戳容差，以及平台回包要求。不得用 viewer 名称作为身份或房间路由。服务端先验证原始消息，再映射四种白名单命令。客户端不执行动态脚本，观众昵称作为纯文本渲染。

正式运营建议对每个房间独立排队和去重，用事件序号支持断线恢复；观众需要获得清晰的结算反馈。当前内存事件桥不承诺持久投递，HTTP accepted 表示事件桥接收，不能作为礼物已产生游戏效果的结算凭证。

## LDtk 地图工作流（计划）

地图设计尺寸 960 × 576，逻辑网格 24px；角色采用约 16 × 32 的像素轮廓。LDtk 建议层：Floor、Walls、Props、Collision(IntGrid)、Entities。实体类型：PlayerSpawn、Fuse、Exit、GhostSpawn、Light。通过导出 JSON 的 `levels[].layerInstances` 读取 IntGrid 与实体位置；转换为独立关卡数据，然后由 Phaser 构建场景。不要将 LDtk 格式耦合到礼物事件系统。

当前几何场景集中在 `src/scene.ts`，替换时应先抽出碰撞矩形和实体坐标，再换图块，保持触发距离与出口逻辑不变。

## Aseprite 素材工作流（计划）

角色动画建议标签：idle_down、walk_down、walk_up、walk_side、hurt；幽灵使用 float、appear、vanish；所有标签统一帧原点。导出 PNG atlas + JSON，由 Phaser `load.aseprite` / `anims.createFromAseprite` 加载。保持最近邻采样，避免平滑缩放；当前程序化角色可在相同容器原点替换。

## 后续优先级

1. 确认 TT 真实协议，接入房间会话、身份验证、实际礼物映射。
2. 用 LDtk 和 Aseprite 替换程序化占位素材，加入第二张地图与随机保险丝位置。
3. 增加空间脚步声和环境音、OBS 干净画面模式、可调惊吓强度。
4. 增加长期观众贡献记录与合作目标；测试高频礼物流下的公平性。
