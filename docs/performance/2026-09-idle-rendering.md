# 主界面和游戏静止时的 CPU 开销

2026-09-11。基线 `354b6ef9963b2b8840177ab4c3f1599c9eda10da`，优化对应本报告随附的光照缓存和静止界面冻结改动。测量使用 Apple M5 Pro、48 GiB、macOS、Chrome 153.0.8010.36 headless，1280 × 800，Vite 开发版本。

## 原因和处理

原先主界面、暂停、结算时仅停止模拟，Phaser 仍每秒绘制约 60 次，约 30 次重算全图光照。光照对每个光源反复排序墙角射线、遍历全部遮挡物，并重新生成家具阴影；站着不动也做相同工作。

- 静止界面在最后一帧和击杀房间截图完成后暂停引擎，并停止 RAF 循环。状态同步或开始新一局时唤醒；重置时间增量，避免补算暂停期间的游戏时间。出口教学的往返镜头继续运行，到停留阶段才冻结。击杀动画由浏览器独立播放。
- 光源遮挡和家具阴影按位置、半径、朝向缓存。亮度变化直接合成，颜色变化只更新染色图；墙、门、家具几何值或画布尺寸变化会使缓存失效。
- 缓存裁剪到光源覆盖范围，只保留当前帧的来源，并复用离开位置的画布，避免手电移动时持续增加缓存或创建画布。
- 删除正常更新中的一次重复礼物面板刷新。暂停时收到礼物仍会同步库存并请求一帧。

没有修改模拟频率、怪物决策或游戏难度。`balance` 诊断模式由回放工具管理更新和暂停，保留其原有执行方式。

## 测量

各状态单独新建浏览器上下文，预热 2.5 秒，采样约 10 秒。游戏为第三夜、seed 0，无移动输入，怪物逻辑照常运行。无其他测试、构建或源码修改与采样重叠。

下表是 **renderer 和 GPU 进程消耗的 CPU 时间之和，按一个 CPU 核心为 100%**，不是显卡利用率，也不是 Windows 任务管理器的整机百分比。浏览器主进程及网络、音频等进程在原始报告中另列。

| 状态 | 优化前 | 优化后 | 降幅 |
| --- | ---: | ---: | ---: |
| 主界面 | 54.1% | 6.4% | 约 88% |
| 游戏内站立 | 62.0% | 38.6% | 约 38% |
| 暂停菜单 | 58.1% | 6.7% | 约 89% |

站立状态仍每秒绘制约 60 帧，10 秒内 301 次光照调用的累计耗时由 1775.4 ms 降到 110.2 ms，约减少 94%。主界面、暂停及静止教学页在采样窗口内均为 0 次游戏绘制、0 次光照计算。页面动画、音频、浏览器及采样工具本身仍会产生开销。

原始结果在 `output/idle-profile/before/` 和 `output/idle-profile/final/`，后者包含源码差异。基线工具最初的 tutorial fixture 没有真正触发教学，**不能用于教学状态的前后比较**；新工具已加入状态断言，修正后的教学页验证了冻结行为。各项为单次采样，具体百分比会受浏览器、系统调度和硬件影响；没有在 Windows/WebView2 上实测 CPU。随后已从包含这些改动的工作区构建 Windows 0.4.7 完整和精简 ZIP，通过包完整性及 Chromium/WebKit 离线前端检查；仍未进行 Windows 原生运行验证。

## 正确性和重复执行

`tests/idle-rendering.browser.mjs` 在 Chromium 和 WebKit 中分别比较 140 次绘制，与 `tests/fixtures/light-renderer-before-idle.ts` 的旧渲染结果逐像素相同。覆盖七夜地图、移动和旋转光源、亮度与色彩、重复位置光源、门和家具原地变更、画布尺寸变化。另检查主界面、开始、暂停、缩放、暂停时收到电池后的画面更新、恢复、怪物教学、出口镜头往返、击杀动画、重试和返回主界面。

`npm test` 通过：222 个普通测试、1,400 组地图，0 回退、1,359 个不同布局；两阶段共 11.5 秒，不含内容准备。最终构建通过，现有的六种击杀来源及完整礼物浏览器回归也通过。日志在 `output/idle-profile/`。

```sh
# 先在单独终端启动 Vite。
npm run dev -- --port 5174 --strictPort

# 性能采样必须单独运行，不与构建、测试或另一浏览器负载重叠。
npm run profile:idle -- output/idle-profile/check

# 正确性检查可在采样结束后执行。
npm run test:browser:idle
BROWSER=webkit npm run test:browser:idle
```

`PROFILE_SECONDS` 可以调整每个状态的采样时长。工具遇到浏览器错误、错误的界面状态或采样期间源码变更会失败。新增性能测量不加入 CPU 测试进程池。
