# 素材与 R2 请求评估

检查时间：2026-09-07。线上 release `20260907T020459Z`，提交 `07504a30f918dcb68454b60171a0feac32af2822`，与本地一致。初次检查为线上只读检查与本地压缩实验；随后用户授权实施压缩，实施结果见文末。尚未上传 R2。

## 部署内容

线上 current 共 150 个文件，68,658,348 bytes（65.48 MiB）。Vite 默认复制整个 public；部署脚本虽然只传 dist，但 dist 已含原始素材。

public 中有 19 个 PNG（30.16 MiB）、16 个 WebP（17.09 MiB）、36 个 MP3、35 个 Opus、36 个生成记录 JSON，以及字体和授权文件。运行时音乐目录只引用 9 首音乐、18 个音效。

按现有 CSS 引用、精灵 manifest、动态场景图和音乐/音效目录取交集，保守保留全部 CSS 引用（包括可能已被后续规则覆盖的背景）：可从发布产物排除 72 个 public 文件、37.89 MiB。部署预计从 65.48 MiB 降到 27.59 MiB，约减少 58%，无需改变画质或音质。这是清单推算，尚未实施构建过滤及验证新产物。

建议构建采用显式发布清单：图片交付文件、当前目录中的 Opus 和 MP3 回退、字体及许可证，加上构建输出的 HTML/JS/CSS。原始 PNG、未引用音频、生成 JSON 留在仓库，不复制到 dist。当前实际使用的 MP3 回退应保留：它是压缩音频兼容路径，删除会破坏 Opus 解码失败时的兜底。

Chrome 全新 context，1440×900，打开生产首页，等待场景图、点击开始、等待音乐就绪。未覆盖所有关卡或其他浏览器。

没有请求 PNG 或 MP3；所有项目请求成功，没有 pageerror。Phaser 把已下载图转为 blob 后产生的 7 次内部加载，不是额外网络下载，已排除。媒体合计 37 个文件，12.11 MiB；CSS/JS 传输有压缩，不能用发布目录体积代表玩家下载量。

图片等资源出现 `CF-Cache-Status: REVALIDATED`；全部 27 个 Opus 为 `DYNAMIC`。当前 Caddy 给素材一小时浏览器缓存，但没有因此让 Opus 自动进入 Cloudflare 边缘缓存。

## 压缩实验

从原 PNG 编码，不重复压缩 WebP；保持分辨率。命令：`cwebp -q 95 -m 6 -alpha_q 100 source.png -o candidate.webp`。FFmpeg 比较原图与候选的 SSIM，背景样本为 YUV 汇总指标。

| 图片 | 现有 WebP | Q95 WebP | 减少 | SSIM |
|---|---:|---:|---:|---:|
| hospital-wall-v2 | 2,058,530 B | 608,880 B | 70.4% | 0.992821 |
| archive-ward-v1 | 1,424,116 B | 286,658 B | 79.9% | 0.992911 |
| watch-desk-v1 | 1,459,970 B | 282,364 B | 80.7% | 0.990283 |

查看过值班桌原图和候选全图，整体构图、暗部及桌面细节保持较好。SSIM 和单张查看不等于全游戏质量验收；发布前仍应在实际显示尺寸下检查暗部、文字、边缘。三张样本共节省 3.59 MiB，不应将比例直接外推全部素材。

角色/精灵图有透明边缘和裁切坐标，建议保留现有无损 WebP，不统一套用有损参数，也不直接缩尺寸。背景可分别试 Q90/Q95 后选取。当前脚本的音乐 Opus 为 64 kbps VBR，音效为 40 kbps；运行中选用的 Opus 比相应 MP3 总计小 47.2%。没有做听音比较，不宣称进一步降码率没有听感影响。

## 请求数量与 R2

按当前 37 个媒体文件、每次都是全新下载、没有边缘缓存、没有失败重试估算：

| 月冷启动次数 | R2 读取次数 | Standard Class B 费用 |
|---|---:|---:|
| 10 万 | 370 万 | $0 |
| 100 万 | 3,700 万 | $9.72 |
| 1,000 万 | 3.7 亿 | $129.60 |

假定账号每月 1,000 万免费 Class B 额度未被其他业务占用，仅计算读取，不包括其他产品。37 次是本次路径的媒体数，并非所有访问的固定上限；关卡场景切换、失败重试、MP3 回退可能增加，缓存和静音访问可能减少。

R2 Standard：10 GB-month 存储、100 万 Class A、1,000 万 Class B 每月免费；超额存储 $0.015/GB-month，Class A $4.50/百万，Class B $0.36/百万，互联网出站流量免费。费用按官方计费单位向上取整。

R2 自定义域名接入 Cloudflare Cache 后，只有到达 R2 的读取才形成相应对象操作，浏览器请求数不等于 R2 读取数。应显式设置包含 `.opus` 的缓存规则，不能仅依赖默认扩展名缓存；使用内容哈希或不可变 release URL 和长缓存，核验首次 MISS、随后 HIT。启用适用的 Tiered Cache 可减少跨节点回源。浏览器跨域加载需设置正确 CORS。r2.dev 用于开发且有限流，不作为正式 CDN。

现有 VITE_ASSET_BASE_URL 只作用于运行时图片和音频；CSS 图片和字体仍走站点 URL，不能认为设置一个变量就迁移了全部静态文件。现有域名已经经过 Cloudflare，也可以先在 Linode 源站方案上配置素材缓存，单独迁移 R2 并不自动保证更快。

## 建议顺序

1. 构建发布清单，排除原图、旧音频和生成记录；保留兼容回退及许可证，新增产物引用完整性检查。
2. 对背景逐张高质量压缩，精灵保留无损，发布使用新资源版本，避免旧缓存混用。
3. 优先验证 Opus 的 Cloudflare 缓存。未来迁移 R2 时使用相同缓存策略。
4. 音乐按当前主题加载与预取，复用已解码 buffer；当前一次加载全部主题存在优化空间。
5. 只有请求规模确有必要时才做音效包。18 个音效合计约 109 KiB，可以合成一个文件加索引，将媒体请求从 37 降到约 20，但需验证切片、尾音、解码和回退。当前规模无需为省请求把所有媒体打成大 ZIP。

资料：[R2 价格](https://developers.cloudflare.com/r2/pricing/)、[公开桶与自定义域名缓存](https://developers.cloudflare.com/r2/buckets/public-buckets/)。

实验数据保存在本机 `/tmp/night-shift-audit/`：network.json、compression.json、delivery-allowlist.json、候选图和浏览器截图。项目依赖安装曾被当前 npm 内部镜像的 Playwright 404 阻断，浏览器检查改用隔离的临时 Playwright 安装完成；未修改 lockfile，也未据此宣称项目构建/测试通过。
