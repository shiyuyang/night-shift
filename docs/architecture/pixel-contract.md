# 像素渲染约定

当前第一阶段统一内部 framebuffer 为 640×384，保持既有 5:3 构图。一个内部像素对应一个世界坐标单位，摄像机缩放 1；地图碰撞、速度和灯光的世界坐标继续沿用。

桌面与足够大的嵌入窗口按整数 CSS 像素放大，并居中留边。容器小于 640×384 时显式退回等比缩小，优先保证界面可访问；该模式不承诺整数像素。浏览器缩放和不同设备 DPR 仍需单独检查。HTML 界面保持独立分辨率。

`game/assets/manifest.json` 为渲染尺寸与角色帧配置来源。现有地砖 24 世界单位，对应 24 内部像素。角色与怪物分别使用 56 和 64 像素帧高；图集方向顺序为下、右、上、左，第二列为静止姿势。

旧生成 PNG 不是原生手工像素工程。尤其 patient 图集尺寸 1278×1230，不能均匀整除四行四列，导入需使用四舍五入的单元边界。运行时统一采样只能稳定像素网格，不能代替美术整理或修复错误动作。

后续 Aseprite 源工程应使用固定整数帧尺寸、共享脚底锚点、明确动画标签，导出 PNG 与帧元数据。当前尚未创建 Aseprite 源工程。病房、仓库、机房均已接入统一 LDtk 加载与独立 JSON 事件；详见 game/README.md。

320×192 的试行方案损失了角色面部细节，因此提高到 640×384，并同步调整相机，保持可见世界范围约 640×384。人物原图的行间距不均匀，watchman.sourceRows 使用显式边界，避免左朝向头顶被四等分裁掉。地图实际边界仍为 960×576，没有随渲染调整而扩大。
