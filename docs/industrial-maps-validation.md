# 仓库与机房扩图验证

分支：`codex/hospital-new-levels`。本轮将药品仓库、地下机房由 960×576 改为 1280×768，沿用病房样板的角色尺度、三箱和钥匙链，不新增耗时机关或怪物规则。

## 实现

- 仓库：六组平行高货架、北/中/南搬运横道，四个功能区分别为收货区、发药间、冷藏间、锁闭药库。散箱集中于收货区。
- 机房：中央四组 160×100 的大型机组，外围检修环与中央维修通路，四个附属工作间。地面管线仅装饰，不产生隐藏碰撞。
- Rack 与 Engine 为独立家具种类，直接按实体占地绘制，并接入完整灯光遮挡；碰撞、AI 视线、玩家与怪物寻路均使用实际占地。
- 三张地图统一采用分用途随机位置池与 Optional*Zone 可选家具区域。病房首关保持固定，后续轮次随机；不改变所需钥匙和箱子数量。
- 旧怪物浏览器测试的场景坐标从旧机房位置迁到新中央通路，避免测试角色出现在新机组内部。

## 自动检查

内容校验、TypeScript、生产构建及 92 项自动测试通过。600 个主题/种子组合得到 452 种物资组合，0 次回退。新增测试覆盖仓库横道、机房检修环的实际移动、分用途搜寻区域，以及补给/藏身柜避开主通道。

固定 A/B 摆放的最短撤离距离：仓库 1216 / 1160，机房 1152 / 1168 世界单位。上述长度计入碰撞和交互半径，不等同于完整局长。

## 浏览器验证

`npm run test:browser:industrial` 对第 2、3 关执行真实键盘移动与钥匙链：先确认门仍锁住，再拿铜钥匙、搜寻前两箱、进入新增南部、开门、开启封箱、返回西侧出口。使用该局实际生成的物资位置，无传送、直接解锁或库存修改。

路线测试每 2 秒调用既有 sanctuary 庇护，隔离难度因素；不修改怪物状态。两张图均完整撤离且没有运行时错误。

另外，`tests/encounters.browser.mjs` 与 `tests/monster-tutorial.browser.mjs` 均通过：覆盖哭泣患者预告、本地/观众闪光、暂停、零电疾跑、畏光者藏身撤离、持续追逐致死，以及四类首次遭遇的遮挡、冻结、确认保护和刷新后记忆。这些测试使用明确构造的遭遇场景，不代表整局无援助通关。

灯光像素检查以实际货架/机组尺寸构建测试光源，并确认游戏渲染器实际接收到遮挡物：货架背后遮罩 alpha 从 80 增至 240，机组背后从 175 增至 240（255 为完全不透明）。同时检查了正常视野截图与关闭遮暗的布局总览。

截图和结构化报告位于 `output/industrial-maps/`；关闭光照遮暗的 overview 仅用于布局评审，不是正常游玩视野。
