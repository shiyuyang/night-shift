# 有约束的随机搜寻

七张地图均为 1280×768。建筑、家具阵列、门、灯与功能分区固定，仅在房间内的候选位置之间随机。首关病房保持固定教学；后续轮次使用可复现种子。

## 受约束的候选点

`game/search-spots.json` 按主题定义 `key` / `task` / `sealed` 三组非空位置池。铜钥匙可在不同的未锁房间出现，前两只任务箱共用 `task` 池；无锁箱和铜锁箱每局分配到不同房间或储物区，最后封箱始终在锁房。

| 地图 | 前两只任务箱的候选区域 | 最后封箱 |
| --- | --- | --- |
| 病房 | 护士站、普通病房、治疗室、布草间 | 隔离室 |
| 仓库 | 收货区、发药间、冷藏区、货架储物区 | 锁闭药库 |
| 机房 | 值班室、工具间、泵房、东侧或南侧检修区 | 配电室 |
| 门诊部 | 挂号区、诊室、检查区、员工室 | 治疗室 |
| 手术室 | 准备间、清洗间、手术区、恢复室 | 无菌库 |
| 太平间 | 值班室、清洁间、辨认区、推车停放区 | 冷藏锁区 |
| 医院中庭 | 门卫室、温室、养护区、长椅附近 | 工具房 |

先随机房间，再选择该房间内的位置，避免大房间因候选坐标多而占据大多数结果。前两只箱子至少相距 180 像素。随机后检查物资身体不重叠、不与家具和门相交，按完整钥匙链验证开门前后的可达性。最多随机尝试 12 次，失败则按固定顺序选择通过同样校验的候选组合，并使用 LDtk 的最终箱位置。不会通过放宽可达性要求接受非法种子。

## 可选家具

第一夜固定四只道具箱，后续四至六只，每局两只有物资；另有一个躲藏柜及按难度配置的一至三只空任务箱。候选区域来自功能房间与储物区，箱体靠近墙壁或家具。额外空任务箱可以放在锁房里，但不会替代必有保险丝的最终封箱。

验证器将柜子的扩大安全区视为障碍，重新验证钥匙链，并检查每个柜子正面均可接近。数量或分布不满足要求时重试布局。完整位置规则见 [箱子与钥匙的位置规则](gameplay/container-placement.md)。

## 撤离约束

EXIT 位于西侧，最后封箱在东侧锁区；必须取得无锁箱和铜锁箱中的钥匙才能进入并开启封箱。最短撤离距离考虑实际可通行位置、开箱半径 44 和出口交互半径 37，要求至少 600 世界单位。

当前 LDtk 固定 A/B 布局分别为：病房 1088 / 1136，仓库 1216 / 1160，机房 1152 / 1168。它们是几何最短路，不包含搜寻、回避追逐和直播互动。

## 验证

`npm test` 先运行普通测试，再运行 1,400 个主题/种子组合。`tests/random-level.test.mjs` 验证种子确定性、固定建筑、跨区域随机性、完整钥匙链、不可达反例和保底流程；全地图池另外检查箱子间距、储物分区、道具箱覆盖与生成数量。最近运行结果见位置规则文档。

`tests/levels.test.mjs` 使用实际玩家与追兵身体尺寸检查病房工作间回环、仓库横道及机房检修环。浏览器入口为 `npm run test:browser:ward-expanded` 和 `npm run test:browser:industrial`，使用真实键盘及交互，有庇护辅助；不作为无援助难度结论。

历史地图结构与交互验证另见 `clinical-maps-validation.md`、`morgue-validation.md` 和 `garden-validation.md`，其中旧版固定物资分工已由上述共享候选池替代。太平间两种抽屉状态仍参与可达性检查。
