# 游戏明暗层次与直播可读性：调整方案

本轮只研究整体对比度，未修改光照、暗部遮罩、素材调色或常驻噪点。基线是本地冷光分支，包含此前苍白之影的近距离落点与提亮，以及本轮的漂浮贴图和送礼提示放大。

建议先提高灯下区域和受光轮廓的区分度，同时保留大面积暗部。全屏统一增亮会暴露更多环境；直接提高全屏对比度又可能把已经很暗的通道细节压掉。这两种都不适合作为第一步。

## 当前证据

- `src/light-renderer.ts` 用不透明度 0.94 的深蓝黑遮罩覆盖场景，停电时为 0.97。灯光通过局部擦除遮罩显露素材，并不直接增加素材自身亮度。
- `src/endless.ts` 的室内地面本身是深灰绿、深褐或深蓝，普通环境灯强度再乘 0.82、半径乘 0.8。手电强度已经是 0.98；继续把这个强度推高的余地很小，需要改光束内的亮度分布或受光素材表现。
- `src/signal-noise.ts` 的全屏颗粒常驻 alpha 为 0.12，叠在暗部之上；事件时另行加强。浏览器实际画面中，细颗粒比一些地面和墙体边缘更醒目。
- 当前 Canvas 的 CSS 仅做 `saturate(0.85)`；暗角是半透明内阴影。没有独立的亮部/中间调处理。

浏览器固定视角观察了病房、仓库、中庭、太平间，分别截取开灯、关手电和停电画面。下表关闭 DOM HUD 后，对截图 RGB 做加权灰度统计（0–255，非线性显示码值，**不是物理亮度、视频范围或平台编码测量**）：

| 场景，手电开启 | 灰度中位数 | 90% 分位 | 灰度小于 32 的像素占比 |
| --- | ---: | ---: | ---: |
| 病房 | 14.6 | 31.1 | 90.7% |
| 仓库 | 13.6 | 26.2 | 93.6% |
| 中庭 | 23.1 | 42.1 | 78.4% |
| 太平间 | 14.4 | 24.2 | 95.1% |

这些单视角样本支持“室内大部分信息挤在很窄的暗部范围”，不能代表整局，也尚不能量化直播压缩造成的损失。中庭明显更亮，应单独调参。

证据目录：`output/contrast-study-20260911/`，包含截图、捕获脚本、场景参数及像素统计。`*-material.png` 是暂时隐藏遮罩与颗粒、用于检查素材底色的诊断画面，不是建议效果。

## 第一轮范围

| 调整 | 建议起点与目的 | 涉及范围 |
| --- | --- | --- |
| 手电与灯池 | 保留现有照射距离、角度和遮挡；抬高光束中近段及灯池中心的可见层次，向外较快衰减。受光区平均灰度提高约 15–25% 作为初始观察目标，避免整片地板泛白。 | `src/light-renderer.ts`、`src/endless.ts` |
| 环境结构 | 优先区分灯下墙沿、门框、地面与家具；必要时只提高相关材质的亮色部分，保留接触阴影。未知区域继续深暗。 | 场景绘制和少数素材 tint；先病房与仓库 |
| 常驻颗粒 | 先比较 alpha 0.12 → 0.05–0.07。保留原有低频抖动与短时故障条纹，事件强度独立计算。 | `src/signal-noise.ts` |
| 怪物轮廓 | 只在已有照明范围内检查头肩、手臂、衣摆是否与背景分开；根据实拍再决定个别 tint。苍白之影已有局部冷光，先沿用。 | 怪物渲染；不添加隔墙轮廓或远处提示 |

第一轮维持暗部遮罩基值与全屏平均亮度接近现状，不扩大照明范围，不改电池、感知、碰撞或难度。以上数值是 A/B 起点，尚未实装或验证。中庭、血月、停电在室内方案确定后分别检查，避免套用同一增益。HUD 独立于场景调色。

## 验收与实施顺序

1. 先在病房、仓库做两个轻量方案：仅减少颗粒；减少颗粒加灯下层次。用同位置、同朝向、同电量与同怪物距离作对照。
2. 覆盖正常移动、快速转向、门口遮挡、怪物进入光束、停电与最后阶段。目标是更快分辨通路和近处威胁，同时暗角仍保留不确定性。
3. 对相同移动序列做本地 720p/30 fps、2 Mbps 与 4 Mbps 的压缩录像比较，再看手机端缩小画面；这些只是测试档位，不宣称是直播平台要求。最终仍需实际直播回看。
4. 测量光照耗时、帧时间和空闲 CPU。沿用现有光照缓存；不做逐帧 CPU 全屏像素读取或自动曝光，避免重新引入卡顿。

确认方向后再实施第一轮，整体光照改动尚未开始。
